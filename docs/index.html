How Many Independent Models Does an Open‑Model Ecosystem Contain?

A pre-registered study of correlated failure across 1,300+ open language models, run at the one conditional null that requires no fitting: the distribution implied by the sufficient statistics of the Rasch model itself.

Shaurya Gupta · high school researcher · shauryaguptaa8@gmail.com

Read the paper (PDF) Short version (4pp) GitHub repository Layer C — live changelog Prior-art ledger

The question

If a dozen AI companies each release a competing model, how many genuinely different screeners does that actually give you?

That question matters wherever multiple models are meant to provide independent evidence — an ensemble, a panel of AI judges, competing resume-screening vendors. If the models all share the same blind spots, the appearance of diversity is doing no real work. A growing body of research measures this by checking how often pairs of models fail on the same test items, compared against a baseline where their failures are assumed unrelated.

That comparison turns out to be broken in a specific, provable way — and fixing it changes the answer.

What almost everyone measures, and why it doesn't mean what it looks like

The standard co-failure statistic is fixed almost entirely by how hard the test items are, not by anything the models are doing. Prove it out with basic algebra and the mean co-failure rate across a population of models depends only on how many models fail each item — never on which models, never on any shared behaviour. Any randomisation that keeps the same item-difficulty pattern reproduces the exact same number every time.

That result already existed — independently, in three different fields (ecology's "V-ratio," psychometrics' Cronbach's alpha, and Fleiss's measure of rater agreement) — and none of them had been connected to how AI models get evaluated. Finding and citing that connection, rather than presenting the identity as new, was itself a correction made partway through this project (see "what didn't survive," below).

What's actually there

Once the item-difficulty artifact is removed by conditioning on it exactly — no curve-fitting, no estimated parameters, just the null implied by the model's own sufficient statistics — a real, second-order signal remains: residual correlation between models that is 5.5 times what the null predicts on ARC (2.9× to 11.9× across the five benchmarks), concentrated in a handful of extra dimensions beyond a single shared notion of "ability."

Simulated control populations rule out the boring explanation (models simply varying in how discriminating their answer choices are) and point toward a real one: a handful of latent skill dimensions the standard one-parameter model doesn't capture — not, as it first appeared, a small number of duplicated models hiding in the data. That last point is now tested rather than assumed: throwing away every model that agrees with another above 95% discards 36–64% of the population and moves these ratios by less than 1.5×.

And one thing the method cannot see, stated plainly because it matters: if every model found exactly the same items hard and differed only in overall skill, this test would be silent. That case is the null. On planted data it detects shared failure modes and copied models easily, but against a purely shared difficulty profile its detection rate is exactly the 5% you'd get by chance.

What didn't survive

The most useful part of this project, for anyone deciding whether to trust it, is what got thrown out.

Claim withdrawn

"1,362 models behave like 24 independent ones." That headline came out of an early run and looked clean. An adversarial review of the whole project — run deliberately against its own results before submission — found that the statistic behind it is algebraically a rescaled measure of average pairwise correlation: it cannot tell one weak shared factor apart from many tight clusters of near-duplicate models. Verified by hand, the claim was pulled and replaced with the diagnostics that can actually tell those two cases apart.

Pre-registered hypothesis, refuted by its own kill condition

The original primary statistic was committed to in writing before the confirmatory run. It came out with an inconsistent sign across benchmarks. The kill condition written in advance said that outcome would count as a refutation, not a reinterpretation — so it's reported as refuted.

A scooping risk, found by searching rather than hoping

A closely related paper (Jo, Garg & Raghavan, Feb 2026) turned up in a deliberate prior-art search on the same public data. Rather than abandon the direction, the project narrowed to the specific open question that paper leaves unanswered — which conditioning null is the non-arbitrary one — and answered it.

A pre-registered test that went against the project's own argument

Part of the analysis predicted that a specific claim in prior work (that more accurate models make more similar mistakes) might be a measurement artifact. Tested directly against real model responses — not simulation — the claim survived almost fully (88% of the effect remains after conditioning). Reported as robust, exactly as committed to in advance.

How it was built

Everything runs on public data and costs nothing to reproduce. Reading only the accuracy column of each evaluation file — 1.4 KB out of a 63 MB file, for the largest benchmark — made it possible to harvest 1,300+ models per benchmark with no GPU, no API budget, and no bulk downloads.

Two data problems had to be found and fixed before any of the above was possible: item identifiers silently changed format partway through the archive's history (a naive join returns zero matched items), and the evaluation harness restructured its output schema mid-way through, moving the accuracy field into a different location. Both are documented in the repository rather than quietly patched over.

A living instrument, not a one-off

The repository re-checks the public archive for newly released models every month, on GitHub's own infrastructure — independent of any one laptop or chat session — and appends one row to a public time series. Nothing about the method changes between runs; the same frozen estimator is simply re-applied to more data, and any future change to the method itself has to go through the same pre-registration discipline as the original study.
